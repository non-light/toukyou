# 東京駅 謎解きゲーム — 四つの物語

この `nazotoki/` が謎解きゲーム専用フォルダです。オリジナルは [main ブランチ](https://github.com/non-light/toukyou/tree/main) に残しています。

東京駅のオリジナル3Dマップを保存したまま、独立したゲーム制作版に追加した第1話です。古い切符の窓から昔の案内を読み、銀の鈴・SQUARE ZERO・赤レンガ駅舎型ポストをたどって、宛先の消えた手紙を届けます。

スマートフォンでは、通常の情報表示を「階・目的地・情報」の1行にまとめています。「情報」から人物選択・手帳・案内・ヒント・仲間・設定を下側の詳細パネルで開けます。第1作のスマートフォン表示では案内を左上、地図を右上に並べます。アプリ内の埋め込み表示では、アプリ側の操作バー用の余白をゲーム内で重ねて確保しません。切符をかざす間はミニマップ・移動ボタン・仲間の名前を隠し、文章と読むボタンを縦に配置します。長い文章は切符の窓の中でスクロールできます。

## 作品ごとに広がる探索範囲

| 作品 | 探索する階 | 追加した体験 |
| --- | --- | --- |
| 第1作 | 1F・B1F（2階層） | 身近な待ち合わせ目印で操作と謎解きに慣れる |
| 第2作 | B1F・1F・M2F・2F（4階層） | 出発する列車の謎を追加し、中間階から新幹線ホームへ |
| 第3作 | 1F・B1F・B2F・B3F・B4F・B5F（6階層） | 京葉線の写真から長い通路を片道でたどり、総武・横須賀線のB5Fへ |
| 第4作 | 1F・B1F（2階層） | 祖母の手帳と二人の記録を読み解き、長く会っていない友人との再会を手伝う |

第1〜3作で全8階層を歩き、第4作では思い出の目印をもう一度訪ねる構成です。第2作は5問、第3作は5問＋最後の撮影。歩く道案内を優先し、移動省略も補助として残しています。駅の形状・階層・通路は変更していません。

第2作の旧記録は新しい段階へ引き継ぎます。第3作の完成写真と結末は保持し、旧版で途中だった記録は新しい探索ルートの最初へ移します。

## 第4作『あの日の約束を、もう一度』

「4作目 あの日の約束を、もう一度」から、紬と祖母の手帳をたどる物語を遊べます。第3作の写真の端に写っていた女性が紬の祖母だったと分かり、長く会っていない友人・澄子との再会を手伝います。B1Fの銀の鈴・動輪の広場・SQUARE ZEROと1Fの赤レンガ駅舎型ポストを巡る、手帳と言葉の謎5問です。SQUARE ZEROは現在の探索地点として扱います。

謎を解くたびに、道を教えたこと、待ち続けたこと、言葉を受け継いだことの理由が分かります。再会の連絡・再会・手帳の奥のページを開く段階を別々に保存し、終盤で第1作の手紙の差出人につながります。第1〜3作の記録はそのまま残ります。

物語・判定は `dist/game/promise-state.js`、画面は `promise.js` / `promise.css`。自動保存、段階ヒント、手帳の再読、歩く道案内と移動省略に対応し、`/play.html?episode=4` で第4作の紹介を直接開けます。連絡や再会はゲーム内の物語として進行します。

## 第3作『写真に写らなかった君』

「3作目 写真に写らなかった君」から、写真を撮るのは好きでも自分が写るのは苦手な青年・律〈りつ〉の物語を遊べます。疎遠になった兄へ送る写真のため、アルバムの風景の切り抜きから場所を探し、三つの撮影位置を切り替えて同じ構図を見つけます。京葉線・総武線の列車の奥行き、動輪の遠近、ポストの左右対称、SQUARE ZEROの柱の間隔を使う5問です。

最後は銀の鈴でカメラを誰かに渡し、律自身が写った写真に短い便りを添えます。第2作の結末にも青年が二人を撮る短い場面を追加しています。最後の写真に写る年配の女性は背景で、手がかりや選択対象にはしていません。

物語と判定は `dist/game/photograph-state.js`、画面は `photograph.js` / `photograph.css`、写真描画は `photograph-camera.js`。写真には既存の3D目印の複製を使い、駅の形・配置は変更しません。実際の駅での撮影位置を示すものではありません。ヒント、写真の文章説明、歩く道案内、地点への移動、作品別の自動保存に対応します。`/play.html?episode=3` で第3作の紹介へ直接進めます。

## 第2作『さよならを言わない待ち合わせ』

「2作目 さよならを言わない待ち合わせ」から、紬〈つむぎ〉として東京駅を歩きます。東京を離れる幼なじみ・晴〈はる〉の「最後の宝探し」を、3D模型から撮影した写真とメッセージでたどる1人用の物語です。写真の場所選び、数を使う文字拾い、頭文字、文字を消す謎の5問を経て、最後の待ち合わせへ向かいます。

解けた行き先へは歩く道案内・その場所へ移動の両方が使えます。スマホのメニューから手帳・段階ヒント・構内地図を開けます。第1作と第2作は「物語」から切り替えられ、記録は別々に端末へ保存されます。第1作の協力部屋から切り替えるときは、先に「仲間」から部屋を退出します。第2作の再スタートには専用の確認画面があります。

物語・正解判定は `dist/game/farewell-state.js`、画面・人物は `farewell.js` と `farewell.css`、物語の切り替えは `episodes.js` と `episodes.css` です。第1作の手紙とのつながりは、この時点では説明しません。駅の形や配置は変えていません。

`?episode=2` を付けて開くと第2作の紹介画面へ進みます（例：公開URLの `/play.html?episode=2`）。初回オンライン読込み後は、第2作の写真もオフライン用キャッシュに含まれます。

## 第1作の遊び方

「物語をはじめる」から開始します。切符が光る場所で「切符をかざす」を押し、目印の方を見て「昔の案内を読む」を選びます。謎は案内を読む・同じ絵を選ぶ・三つの印を順に並べるの3段階です。最後は手紙を開いて投函します。

制限時間や失敗のペナルティはありません。発見は手帳に記録され、ヒントを段階的に表示できます。「道案内」から歩いて案内させたり、目印の前へ移動したりできます。ソロの進行はブラウザ内に保存されます。

「仲間」から最大4人の部屋を作成できます。合言葉または招待リンクで参加し、発見・謎の進行・手帳を共有します。同じ階の仲間は3D表示されます。部屋は24時間有効で、しばらく接続していない人の席は新規参加時に解放されます。部屋の再接続情報はそのタブに保存します。公開URLを開き、合言葉で参加できます。接続が終了した場合や部屋の期限が切れた場合は、再参加または1人で続ける画面を表示し、それまでの発見を手帳に保存します。

赤・青・緑・黄の4人の3D旅人を選べます。ゲーム中は人物の右肩の後方から追従する肩越し視点です。壁がカメラに近づくと距離を詰め、近すぎる自分の人物は透過します。開始画面や「自分の旅人を選ぶ」で、選んだ姿が立体表示されます。協力プレイでは他の参加者と色が重ならず、同じ階の仲間の歩行・走行も表示します。オリジナルのGLBとCC0ライセンスは `dist/game/avatars` に同梱しています。

既存の自由散策、マップ、階移動、設定、制作画面も利用できます。制作画面で追加した人物や謎のデータは、このエピソードの進行とは別に保存します。

## 物語と進行の整合性

第1作では、プレイヤーに届いた手紙を読み、次の旅人へ託す意味を結末まで明示しています。投函後も本文を読み返せます。最初から遊び直すときは記録の初期化を確認します。

第2作は同じ頭文字拾いの連続を避け、語末二文字をつなぐ謎を挟んでいます。晴と会う段階と、青年に二人の写真を撮ってもらう段階を別に保存し、撮影まで物語をつなぎます。旧版のクリア記録は維持します。隣の新幹線ホームでは解答できません。

第3作のヒントは、見方→地点→視点の順に整理しました。送信後の案内は写真帳の再読へ変わります。スマートフォンではマップだけを右上の小さな四角に表示し、アプリ内の埋め込み表示でも進行バーと重ならない位置にします。

作品を切り替えるとページの題名とリンクもその作品に変わり、再読込で同じ作品に戻れます。駅の形・階・通路・列車・目印のデータは変更していません。

## 開発と検証

初回の準備（Node.js 22.13以上）：

```sh
cd nazotoki/server-app
npm ci
cd ..
npm start
```

Sitesのビルド補助がない環境では、同梱のビルドスクリプトを使用します。ゲームの操作や謎の内容は、公開中の制作版と同じです。


```sh
npm run check
npm test
npm start
```

`npm start` はゲームのファイルを `server-app/public` へコピーし、協力APIをビルドし、ローカルのDBに未適用の変更を反映してから `http://127.0.0.1:4175` で起動します。別のポートは `npm start -- --port 4188` で指定できます。Node.js 22.13以降を使用し、初回は `nazotoki/server-app` で `npm ci` を実行してください。その後 `nazotoki` に戻って `npm start` を実行します。

著作ファイルは引き続き `dist/` 直下にあります。`dist/server`・`dist/client`・`dist/.openai` はビルド生成物で、直接編集しません。協力APIとDB定義は `server-app`、公開用DB変更は `drizzle` にあります。オンライン協力にはサーバー接続が必要です。

```sh
npm run build
```

公開先は独立したゲーム制作版 `appgprj_6aec2c90b13c8191bb14c9c12644b58d` です。オリジナルのサイトIDへ変更しないでください。GitHubのオリジナルmainブランチには反映しません。

### 第4作の手帳を作り込んだ点

祖母の三つの車輪の絵を実際の手描き風図で表示します。短い返事は、祖母と澄子の文字を一文字ずつ選んでつなげられ、キーボードでの直接入力も使えます。並べた記録から五分のすれ違いをたどり、各謎で分かった行動の理由は、手帳にも残ります。

終盤はページごとに会話の読んだ位置を保存し、手紙のページ・最後の会話の途中から再開できます。旧版の探索・再会・クリア記録も引き継ぎます。5問の正解と探索する場所は共通です。

### 第1〜4作を通した修正

協力部屋を退出したときも第1作の共有した発見・クリア記録を手帳へ引き継ぎます。第2作はヒントや写真拡大から戻っても入力途中の答えと文字盤の消去状態を保ち、第2・3作の終盤の会話は読んでいた台詞から再開します。第3作の案内は撮影・送信・会話の段階に合わせ、写真表示が中断された場合は文章の手がかりを使えます。

第4作の待ち合わせの答えは、漢字・ひらがな・数字が混ざった正しい時刻表記も受け付けます。第1作の手紙とのつながりは、主人公の名前を決めつけず、プレイヤーへの地の文で伝えます。オフラインの読み込み先をそろえ、作品を指定したURLからも保存済みの画面を開けるようにしています。協力APIはオンライン接続が必要です。駅の形や配置は変更していません。
